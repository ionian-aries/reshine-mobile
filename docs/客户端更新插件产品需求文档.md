# Reshine Mobile 客户端更新插件产品需求文档

## 1. 文档目标

本文定义 `reshine-mobile/local` 接入 Android 客户端更新管理服务的产品需求、接口契约、插件架构、页面接入方式、异常策略、安全约束和验收标准。

本期目标是在经典 uni-app（Vue 2、Vue CLI）项目中，以纯 JavaScript `uni_modules` 插件实现 APK 整包更新与 WGT 资源包更新。插件不依赖自定义原生模块，直接封装 uni-app 与 HTML5+ 提供的 `uni.request`、`uni.downloadFile`、`plus.runtime.getProperty`、`plus.runtime.install`、`plus.runtime.restart`。

结论：**可以设计为纯 JavaScript 插件，且这是当前项目的最优方案。** 更新能力均已有运行时 API 支持，无需仿照 `local-rpc-server` 增加原生插件；只复用其 Promise API、参数校验、统一错误模型和幂等设计。

## 2. 背景与现状

### 2.1 当前工程

- 客户端工程：`reshine-mobile/local`。
- 技术栈：经典 uni-app、Vue 2、Vue CLI 5、webpack。
- 应用标识：`__UNI__526C783`。
- 当前 APK 版本：`1.0.0`，版本代码 `100`。
- 首页是承载本地 H5 的 `web-view`，页面逻辑应保持精简。
- 当前 `local/.env` 已定义业务接口变量 `VUE_APP_LOCAL_API_BASE_URL`；更新插件与该业务接口配置完全隔离，不读取且不允许回退到该变量。
- `online/.env` 通过 `VUE_APP_WEBVIEW_URL` 配置在线页面地址，证明本工程采用 `process.env.VUE_APP_*` 编译期注入。

### 2.2 更新中心既有约束

- 只支持 Android APK 与 WGT，不支持 iOS、HarmonyOS、小程序、应用市场和 Scheme。
- 客户端提交 AppID、APK 版本、WGT 版本。
- 服务端每次最多选择一个更新包，兼容 WGT 优先，否则选择 APK。
- 更新完成并重启后再次检查，以串行完成剩余更新。
- 既有设计采用强制更新，临时下载文件不跨页面或跨启动持久化。

### 2.3 文档审阅发现的契约问题

实现前必须确认并修正文档/后端契约：

1. 请求字段曾存在命名冲突。本文及实现统一采用 **`apkVersion`**；客户端只发送 `apkVersion`，禁止发送或兼容 `appVersion`，避免契约长期分叉。
2. 响应协议统一规定：业务成功为 `code = 200`，此时 `data.action` 只允许 `none` 或 `update`；业务失败必须为 `code != 200`，`data` 为 `null` 或不包含 `action`。
3. 既有客户端设计只校验少数字段，供应链保护不足。本文要求插件增加本地契约校验、防降级校验、HTTPS/可信域名控制；服务端后续应增加文件摘要。
4. “任何检查失败都进入不可关闭页面”会导致断网或服务故障时应用永久不可用。本文区分“尚未确认有强制更新”和“已确认强制更新”两种状态，避免启动死锁。

## 3. 产品目标与非目标

### 3.1 产品目标

1. 应用启动后以一个简单入口完成版本采集与更新检查。
2. 页面层最多调用一个高阶 API，不处理平台细节和协议细节。
3. 更新检查完整 URL 通过 `local/.env` 中唯一的 `VUE_APP_UPGRADE_CHECK_URL` 配置，代码内不硬编码且不存在回退地址。
4. 同时支持 APK 和 WGT 下载、安装、进度反馈及失败重试。
5. 明确强制更新边界，避免网络故障阻塞正常启动。
6. 提供稳定错误码和流程事件，便于页面展示、日志与测试。
7. H5 等非 App 平台可以正常构建，调用时返回明确“不支持”结果。

### 3.2 非目标

- 不实现后台版本发布管理。
- 不在客户端自行决定线上 APK/WGT 的优先级；选择仍由服务端完成。
- 不支持 iOS 安装包更新。
- 不实现断点续传、后台下载、跨启动复用安装包。
- 不实现自定义原生插件。
- 不在 `.env` 中保存令牌、签名密码、App Key 等秘密。
- MVP 不提供完整更新 UI 组件；插件负责能力与状态，页面负责展示。

## 4. 用户与核心场景

### 4.1 普通启动

应用启动，插件读取实际版本并请求更新服务；服务端返回 `none`，应用直接进入本地 H5 页面。

### 4.2 WGT 更新

服务端返回 WGT。客户端展示更新信息，下载并安装 WGT，成功后调用 `plus.runtime.restart()`；重启后再次检查。

### 4.3 APK 更新

服务端返回 APK。客户端下载后调起 Android 系统安装器。用户完成覆盖安装后重新启动应用，插件再次检查。

### 4.4 异常恢复

- 尚未确认存在强制更新时，检查超时或服务不可用：记录/提示，允许应用进入；可稍后重试。
- 已确认存在强制更新时，下载或安装失败：保持更新页面，允许重试。
- 返回数据非法、AppID 不匹配、目标版本未提升、URL 不可信：拒绝安装并呈现可诊断错误。

## 5. 最佳系统架构

### 5.1 总体架构

```text
local/.env
   │ Vue CLI 自动注入 VUE_APP_UPGRADE_CHECK_URL
   ▼
页面/App 启动入口
   │ await updater.checkAndUpdate(options)
   ▼
app-upgrade 纯 JS uni_modules 插件
   ├─ 配置与参数校验
   ├─ 平台和当前版本采集
   ├─ 更新检查 HTTP 客户端
   ├─ 响应契约与安全校验
   ├─ 下载任务与进度事件
   ├─ APK/WGT 安装适配器
   └─ 流程锁、状态与错误模型
   │
   ├─ uni.request / uni.downloadFile
   └─ plus.runtime.getProperty/install/restart
        │
        ▼
更新管理服务 + HTTPS 文件存储/CDN
```

### 5.2 推荐目录

```text
reshine-mobile/local/src/uni_modules/app-upgrade/
├── package.json
└── js_sdk/
    ├── index.js          # 公共 API 和流程编排
    ├── config.js         # 环境变量及调用参数归一化
    ├── errors.js         # UpgradeError 和错误归一化
    ├── contract.js       # 请求、响应、版本与 URL 校验
    └── runtime.js        # uni/plus 平台能力适配
```

MVP 若要求极致精简，可将上述逻辑合并到 `js_sdk/index.js`，但公共 API 与模块边界保持不变，以便后续拆分。

### 5.3 为什么不需要原生模块

`local-rpc-server` 的 JS 层依赖 `uni.requireNativePlugin()`，其核心服务由 APK 内原生模块提供。升级场景不同：网络、下载、获取应用属性、安装及重启已经由 uni-app/HTML5+ 提供。因此升级插件可完全由 JavaScript 编排，降低原生打包、授权、兼容和维护成本。

### 5.4 页面与插件职责

插件负责：

- 平台识别和版本采集。
- 配置、请求和响应校验。
- 单次流程锁，避免重复检查/下载/安装。
- 下载任务和进度回调。
- APK/WGT 安装分派。
- 错误标准化、任务取消和资源释放。

页面负责：

- 决定何时调用检查。
- 根据事件展示标题、说明、进度、重试按钮。
- 在确认强制更新后拦截返回操作。
- 页面卸载时调用 `dispose()` 取消仍在执行的下载。

服务端负责：

- 版本格式校验和更新资格判断。
- WGT 兼容性及 APK/WGT 优先级选择。
- 保证同一 `appid + type` 至多一个线上版本。
- 返回可信下载地址及后续新增的摘要、大小等元数据。

## 6. 环境配置设计

### 6.1 `.env` 配置

在 `reshine-mobile/local/.env` 中增加唯一且独立的完整更新检查接口 URL：

```dotenv
# 现场局域网业务接口，已有变量；升级插件不得读取
VUE_APP_LOCAL_API_BASE_URL=https://example.com

# 完整更新检查接口 URL，必须包含协议、主机、路径
VUE_APP_UPGRADE_CHECK_URL=https://upgrade.example.com/api/v1/upgrade/check
```

变量名确定为 `VUE_APP_UPGRADE_CHECK_URL`：语义是“更新检查接口完整地址”，带有 Vue CLI 自动暴露所需的 `VUE_APP_` 前缀，但不含 `BASE`。插件不再拆分“服务基址”和“接口路径”，不提供默认 URL，并且在任何情况下都不得读取或回退到 `VUE_APP_LOCAL_API_BASE_URL`。

`.env.example` 使用占位地址，不提交敏感信息。更新检查超时和下载域名白名单优先作为插件默认值或显式初始化参数管理，不参与检查 URL 拼接，也不能成为 URL 缺失时的替代来源。

### 6.2 Vue CLI 自动注入方案

Vue CLI 会自动向客户端代码暴露 `VUE_APP_*` 变量，因此本方案使用 `VUE_APP_UPGRADE_CHECK_URL`，无需新增 `vue.config.js` 或 webpack `DefinePlugin`：

1. 构建环境从 `local/.env` 读取 `VUE_APP_UPGRADE_CHECK_URL`。
2. 插件通过 `process.env.VUE_APP_UPGRADE_CHECK_URL` 读取完整接口 URL。
3. 插件初始化时校验变量存在，并且是包含协议、主机和路径的完整 URL；缺失或非法时返回 `CONFIG_MISSING` 或 `CONFIG_INVALID`，不发送请求。
4. 插件不读取其他业务接口变量，不拼接默认基址或默认路径。
5. 自动化测试必须验证变量缺失或非法时初始化失败，以及插件不存在隐式回退行为。

### 6.3 环境变量语义

- 插件读取 `process.env.VUE_APP_UPGRADE_CHECK_URL`，不使用 `import.meta.env`。
- `VUE_APP_UPGRADE_CHECK_URL` 是完整接口 URL，例如 `https://upgrade.example.com/api/v1/upgrade/check`，不得再拼接路径。
- 该变量是构建期公开常量，修改后必须重新构建 APK/WGT 才会生效。
- 若产品要求“不重新发包即可动态切换接口地址”，仅靠 `.env` 无法实现，需要远程配置或受控本地配置文件；本期不纳入。
- 正式环境必须使用 HTTPS。开发环境如必须使用 HTTP，应显式开启开发开关，并确认 Android 网络安全配置。
- 变量值会进入客户端产物，不得包含令牌、签名密码、App Key 或其他秘密。

## 7. 接口契约

### 7.1 请求

```http
POST {VUE_APP_UPGRADE_CHECK_URL}
Content-Type: application/json
```

```json
{
  "appid": "__UNI__526C783",
  "apkVersion": "1.0.0",
  "wgtVersion": "1.0.0"
}
```

字段定义：

- `appid`：当前 uni-app AppID。
- `apkVersion`：当前原生 APK 的 `versionName`，固定三段非负整数。
- `wgtVersion`：当前运行 WGT 的版本，固定三段非负整数。

版本代码 `versionCode` 可作为后续增强字段，但不能替代当前服务端约定的语义版本。

### 7.2 无更新响应

```json
{
  "code": 200,
  "message": "success",
  "data": { "action": "none" }
}
```

### 7.3 有更新响应

```json
{
  "code": 200,
  "message": "success",
  "data": {
    "action": "update",
    "package": {
      "id": "version_wgt_1",
      "appid": "__UNI__526C783",
      "title": "资源更新 1.1.0",
      "contents": "修复已知问题",
      "type": "wgt",
      "version": "1.1.0",
      "min_uni_version": "1.0.0",
      "url": "https://download.example.com/app-1.1.0.wgt",
      "sha256": "可选，建议服务端尽快提供",
      "size": 12345678
    }
  }
}
```

### 7.4 失败响应

```json
{
  "code": 40001,
  "message": "invalid apkVersion",
  "data": null
}
```

业务失败响应必须满足 `code != 200`，此时 `data` 为 `null` 或不包含 `action`。只有 `code = 200` 时才解析 `data.action`，且仅接受 `none` 或 `update`。

### 7.5 客户端强制校验

插件不得完全信任服务端，至少校验：

- `code` 的类型和值；仅当 `code = 200` 时校验 `data.action`，并且只接受 `none` 或 `update`。
- 更新包 `id/appid/title/contents/type/version/url`。
- WGT 的 `min_uni_version`。
- `package.appid` 与当前 AppID 一致。
- 所有版本为三段非负整数。
- APK 目标版本严格高于当前 APK；WGT 目标版本严格高于当前 WGT。
- WGT 最低 APK 版本不高于当前 APK。
- URL 协议和下载域名符合配置。
- 若服务端提供 `size/sha256`，校验大小和摘要；摘要能力应作为生产上线前的优先增强项。

本地校验只是最后防线，不替代服务端选择规则。

## 8. 插件公共 API

### 8.1 最小公共接口

```js
import updater from '@/uni_modules/app-upgrade/js_sdk/index.js'

const result = await updater.checkAndUpdate({
  onStateChange(state) {},
  onProgress(progress) {}
})
```

默认导出：

```js
{
  check,
  download,
  install,
  checkAndUpdate,
  retry,
  dispose,
  getState
}
```

### 8.2 API 定义

#### `check(options?)`

采集版本并请求服务端，返回：

```js
{ action: 'none', current }
// 或
{ action: 'update', current, package }
```

#### `download(packageInfo, options?)`

创建 `uni.downloadFile` 任务，通过 `onProgress` 返回：

```js
{
  progress: 0,
  totalBytesWritten: 0,
  totalBytesExpectedToWrite: 0
}
```

成功返回 `{ tempFilePath }`。HTTP 状态码必须为 200。

#### `install(localPackage, packageInfo)`

- APK：调用 `plus.runtime.install(filePath, { force: false })`；成功回调只表示安装器调用链成功，不等于 APK 已覆盖完成。
- WGT：调用相同安装 API，成功后调用 `plus.runtime.restart()`。

#### `checkAndUpdate(options?)`

高阶流程：检查 → 返回无更新，或发出更新事件 → 下载 → 安装。默认可设置 `autoDownload: false`，由页面确认后再执行；本项目强制更新模式可设为 `true`。

#### `retry()`

按当前失败阶段重试：检查失败重试检查，下载/安装失败重新下载后安装。

#### `dispose()`

中止下载任务、清除监听和临时状态。必须幂等。

#### `getState()`

返回只读状态快照。

### 8.3 状态模型

建议使用单一、明确的有限状态，避免多个布尔值产生矛盾组合：

```text
idle
→ checking
→ no-update
→ update-available
→ downloading
→ downloaded
→ installing
→ awaiting-apk-restart | restarting-wgt
→ failed
```

状态至少包含：

```js
{
  phase,
  current,
  packageInfo,
  progress,
  error,
  mandatoryConfirmed
}
```

插件维护模块级共享 Promise/流程锁：同一时刻只允许一个检查和一个下载/安装流程。重复调用返回同一个进行中 Promise 或 `FLOW_IN_PROGRESS`，不能产生并发安装。

### 8.4 错误模型

```js
class UpgradeError extends Error {
  code
  message
  data
  retryable
  phase
}
```

基础错误码：

- `UNSUPPORTED_PLATFORM`：非 Android App 环境。
- `RUNTIME_UNAVAILABLE`：`plus.runtime` 尚不可用。
- `CONFIG_MISSING`：完整更新检查 URL 缺失。
- `CONFIG_INVALID`：完整更新检查 URL、协议或主机非法。
- `VERSION_UNAVAILABLE`：无法取得版本。
- `CHECK_TIMEOUT` / `CHECK_NETWORK_ERROR` / `CHECK_HTTP_ERROR`。
- `SERVER_ERROR`：服务端返回 `code != 200`。
- `INVALID_RESPONSE`：协议不合法。
- `APPID_MISMATCH`。
- `VERSION_DOWNGRADE_REJECTED`。
- `UNTRUSTED_DOWNLOAD_URL`。
- `DOWNLOAD_FAILED` / `DOWNLOAD_HTTP_ERROR` / `DOWNLOAD_CANCELLED`。
- `PACKAGE_INTEGRITY_FAILED`。
- `INSTALL_FAILED`。
- `FLOW_IN_PROGRESS`。

错误消息可展示给用户，但页面逻辑只依赖稳定 `code/phase/retryable`。

## 9. 页面使用姿势

### 9.1 推荐启动位置

更新检查属于应用级能力，最佳调用点是 `App.vue` 的 `onLaunch/onShow` 与运行时就绪后的初始化，而不是长期耦合在 `web-view` 页面中。若本期仅修改首页，则在首页 `onReady` 调用一次，并在 `onUnload` 清理。

### 9.2 最简页面示例

```vue
<script>
import updater from '@/uni_modules/app-upgrade/js_sdk/index.js'

export default {
  data() {
    return {
      upgradeState: updater.getState()
    }
  },
  async onReady() {
    try {
      await updater.checkAndUpdate({
        autoDownload: true,
        onStateChange: state => {
          this.upgradeState = state
        },
        onProgress: progress => {
          this.upgradeState = {
            ...this.upgradeState,
            progress
          }
        }
      })
    } catch (error) {
      // 未确认存在强制更新时允许进入应用；
      // 已确认强制更新时由更新层展示重试。
      console.error('[app-upgrade]', error.code, error.message)
    }
  },
  onBackPress() {
    return Boolean(this.upgradeState.mandatoryConfirmed)
  },
  onUnload() {
    updater.dispose()
  }
}
</script>
```

实际首页继续只负责 `web-view`，更新 UI 推荐做成同页覆盖层或独立更新页面。独立页面更适合拦截返回键和呈现失败重试，但路由前必须保留更新包状态，或通过插件模块状态读取。

### 9.3 使用原则

- 模块导入时不自动请求、不自动安装，避免副作用和 H5 构建问题。
- 所有 `plus` 访问延迟到函数内部，并用 `APP-PLUS` 条件编译或运行时检查保护。
- 检查成功且明确返回更新后，才进入强制更新态。
- 页面卸载只取消下载；安装已交给系统后不能假定可取消。
- APK 安装回调后状态设为 `awaiting-apk-restart`，不能标记为已升级。

## 10. 详细流程策略

### 10.1 启动检查

1. 确认 Android App 环境和 runtime 可用。
2. 合并默认配置、环境变量与调用参数。
3. 获取 AppID、APK 版本和 WGT 版本。
4. 校验三个值，缺失则不发送请求。
5. 发起带超时的检查请求。
6. 严格解析响应。
7. `none`：结束并加载业务页面。
8. `update`：设置 `mandatoryConfirmed=true`，进入下载/安装流程。

### 10.2 检查失败的可用性策略

- **尚未收到合法 update**：网络、超时、服务端异常不应将用户锁死在不可关闭页面。显示非阻塞提示并允许业务继续，后台或下次启动重试。
- **已收到合法 update**：进入强制更新态后，下载/安装失败保持更新页面并提供重试。
- 若业务明确要求“服务不可达也禁止进入”，应作为单独的高风险开关，默认关闭，并提供超时后的运维解锁方案。

### 10.3 下载

- 使用 `uni.downloadFile`。
- 保存下载任务引用并注册进度监听。
- 只接受 HTTP 200。
- 临时文件仅在当前流程使用。
- 用户重试时废弃旧路径并新建任务。
- `dispose()` 调用任务 `abort()`。
- 对下载大小设置服务端上限和客户端合理上限，防止异常大文件耗尽空间。

### 10.4 安装

WGT：

1. 校验后缀/元数据和完整性。
2. `plus.runtime.install(path, { force: false })`。
3. 成功后立即 `plus.runtime.restart()`。

APK：

1. 校验下载源、摘要和目标版本。
2. 调起系统安装器。
3. 用户返回原应用时仍显示更新态，可重新调起；临时文件失效则重新下载。
4. 应用重新启动后以实际版本为准重新检查。

### 10.5 多包串行更新

服务端每次仅返回一个包。插件不在内存中循环安装多个包：每次安装后重启，重新采集真实版本并再次检查。这样可避免用预期版本代替实际版本。

## 11. 功能清单与优先级

### P0：首版必须

- 纯 JS `uni_modules` 插件骨架。
- `.env` 中 `VUE_APP_UPGRADE_CHECK_URL` 的 Vue CLI 自动注入与严格读取。
- Android App 平台保护。
- AppID/APK/WGT 版本采集。
- 更新检查请求、超时、响应校验。
- 本地版本防降级与 WGT 兼容兜底。
- APK/WGT 下载、进度、失败重试、取消。
- APK/WGT 安装分派与 WGT 重启。
- 单流程锁和有限状态。
- 统一错误码。
- 最简页面接入。

- 远程动态服务发现。
- 回滚策略、发布审批和审计。

## 12. 安全与合规要求

1. 生产检查接口和下载地址使用 HTTPS。
2. 下载 URL 只允许配置的协议和主机；审慎处理 30x 重定向后的最终主机。
3. `.env` 中不得存放秘密，因为 `VUE_APP_UPGRADE_CHECK_URL` 会在构建时注入客户端产物。
4. 插件拒绝 AppID 不一致、目标版本未提升、WGT 不兼容的包。
5. 优先补充 `sha256` 和 `size`；没有完整性元数据时，应在风险评审中明确记录。
6. APK 必须使用与当前应用一致的签名，否则 Android 无法覆盖安装；发布流程必须校验。
7. WGT 不能承载新增原生权限和原生模块，涉及原生能力变化必须发布 APK。
8. 服务端线上版本应不可原地替换文件；修改包内容应创建新版本，保留审计记录。

## 13. 兼容性要求

- 支持：经典 uni-app Android App。
- 构建兼容：H5/小程序构建不得因顶层引用 `plus` 失败。
- H5/iOS/小程序调用返回 `UNSUPPORTED_PLATFORM`，不尝试下载或安装。
- 覆盖 Android 目标版本、主流厂商 ROM、未知来源安装权限、安装器取消和签名不一致场景。
- WGT 版本必须与 `manifest.json`/打包配置一致，并验证 `min_uni_version`。

## 14. 测试与验收

### 14.1 单元测试

- 三段版本比较：大于、等于、小于、前导零、非法段数、超大整数、空字符串。
- 完整 `VUE_APP_UPGRADE_CHECK_URL` 的读取、合法性校验、缺失或非法时初始化失败和无回退行为。
- `none/update` 响应解析。
- `apkVersion` 契约防回归，并验证请求中不存在 `appVersion`。
- 缺字段、错误类型、未知 action、`code != 200`。
- AppID 不匹配、降级包、WGT 不兼容、非可信 URL。
- 流程锁、重复调用、`dispose()` 幂等。
- 错误归一化和可重试属性。

### 14.2 集成测试

- 请求超时、断网、DNS/TLS、HTTP 非 2xx、服务端业务错误。
- 302 重定向、下载中断、非 200、文件截断、低存储、取消下载。
- APK 调起安装、用户取消、未知来源权限拒绝、签名不一致。
- WGT 安装成功/失败、AppID 不匹配、重启失败。
- 前后台切换、页面卸载、应用被杀、冷启动恢复。
- 同时触发多次检查时只有一个真实请求/流程。

### 14.3 服务端联调矩阵

- 无 APK/无 WGT → `none`。
- 仅 APK 新版本 → APK。
- 仅兼容 WGT 新版本 → WGT。
- APK/WGT 均可用 → WGT 优先。
- WGT 不兼容且 APK 可用 → APK。
- WGT 不兼容且 APK 无需更新 → `none`。
- 同类型多条线上记录 → 明确失败码。
- 更新后重启，再次检查并获取剩余包。

### 14.4 验收标准

1. 修改 `VUE_APP_UPGRADE_CHECK_URL` 并重建后，请求发送到该完整地址；变量缺失或非法时插件初始化失败，且插件不会回退到 `VUE_APP_LOCAL_API_BASE_URL`。
2. 无更新时不影响首页 `web-view` 加载。
3. 尚未确认更新时，检查服务不可用不会永久阻塞应用。
4. 合法更新只下载一个服务端返回的包。
5. 下载进度可见，失败可重试，不产生并发任务。
6. APK 能调起系统安装器；回到旧应用后仍可继续处理。
7. WGT 安装成功后重启，并以真实版本再次检查。
8. 非 Android App 平台可正常构建且不触发安装 API。
9. 非可信地址、AppID 不匹配、降级版本、WGT 不兼容均被拒绝。
10. 页面卸载能中止下载并清理监听，不遗留活动任务。

## 15. 实施步骤

1. 与后端统一 `apkVersion` 字段及 `code != 200` 的失败响应格式。
2. 在 `local/.env` 与 `.env.example` 增加唯一的 `VUE_APP_UPGRADE_CHECK_URL`，由 Vue CLI 自动注入客户端代码。
3. 创建 `local/src/uni_modules/app-upgrade` 纯 JS 插件。
4. 先实现契约、错误和版本测试，再实现 runtime 适配。
5. 在 `App.vue` 或首页接入一次 `checkAndUpdate()`。
6. 增加最小更新覆盖层/页面与重试交互。
7. 使用测试服务器完成 APK/WGT 全矩阵联调。
8. 完成 HTTPS、下载域名和包完整性风险评审后再生产发布。

## 16. 最终决策摘要

- **插件形态**：纯 JavaScript `uni_modules`，无需自定义原生模块。
- **页面姿势**：应用启动处一次调用 `checkAndUpdate()`；页面只订阅状态和进度。
- **配置方式**：唯一完整 URL 变量为 `VUE_APP_UPGRADE_CHECK_URL`，由 Vue CLI 自动注入；不拆分基址和路径、不设置默认值、不回退业务接口变量，修改后需重建。
- **协议决策**：请求字段统一为 `apkVersion`；`code = 200` 时 action 仅允许 `none/update`；失败必须 `code != 200` 且不使用错误 action。
- **可靠性决策**：采用有限状态与单流程锁；下载可取消，清理幂等。
- **可用性决策**：只有确认存在强制更新后才锁定页面；检查服务故障默认不锁死应用。
- **安全决策**：客户端执行 AppID、版本、兼容性和 URL 校验；生产要求 HTTPS/域名白名单，优先补齐 SHA-256 与大小校验。
