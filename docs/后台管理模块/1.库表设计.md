# Android APK/WGT 升级中心库表设计

## 1. 表名映射

| 重实现表名 | 原项目真实表名 |
|---|---|
| `upgrade-app` | `opendb-app-list` |
| `upgrade-app-versions` | `opendb-app-versions` |

本设计仅保留 Android APK/WGT 升级所需的两张业务表。`upgrade-app-versions.appid` 对应 `upgrade-app.appid`，一个应用可以有多条版本记录。

## 2. `upgrade-app`

保存应用基本信息。

### 2.1 表结构

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `id` | long | 是 | 数据库生成 | 记录主键 |
| `appid` | string | 是 | 无 | 应用 AppID，也是版本归属标识 |
| `packageName` | string | 是 | 无 | Android APK 包名 |
| `name` | string | 是 | 无 | 应用名称 |
| `description` | string | 否 | 无 | 应用说明 |

### 2.2 表属性

- `id` 为主键。
- `appid` 唯一。
- `upgrade-app-versions.appid` 通过 `appid` 关联本表。

## 3. `upgrade-app-versions`

保存 APK/WGT 版本、下载地址和上线状态。

### 3.1 表结构

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| `id` | long | 是 | 数据库生成 | 版本记录主键 |
| `appid` | string | 是 | 无 | 对应 `upgrade-app.appid` |
| `title` | string | 是 | 无 | 更新标题 |
| `contents` | string | 是 | 无 | 更新内容 |
| `type` | string | 是 | 无 | 安装包类型：`apk` 或 `wgt` |
| `version` | string | 是 | 无 | APK 或 WGT 的 `versionName`，固定为 `x.y.z`（主.次.修改） |
| `min_uni_version` | string | WGT 必填 | 无 | 安装 WGT 所需的最低原生 App `versionName`，固定为 `x.y.z`；APK 不保存该字段 |
| `url` | string | 是 | 无 | APK/WGT 下载地址 |
| `stable_publish` | boolean | 是 | `false` | 是否为已上线版本 |
| `createdTime` | datetime | 是 | 数据库生成 | 版本记录创建时间，用于列表倒序排列 |

### 3.2 字段取值与约束

| 属性 | APK | WGT |
|---|---|---|
| `type` | `apk` | `wgt` |
| `min_uni_version` | 不保存 | 必填 |

- `version` 和 WGT 的 `min_uni_version` 均以字符串保存，格式固定为 `x.y.z`；`x`、`y`、`z` 分别表示主版本号、次版本号和修改版本号，且均为非负整数。
- 同一应用的 APK 和 WGT 共用版本号序列，`version` 不得重复；例如 APK 可为 `1.1.0`，后续 WGT 可依次为 `1.1.1`、`1.1.2`。
- `stable_publish=true` 表示已上线版本，`false` 表示未上线版本。
- 同一应用、同一包类型最多有一个 `stable_publish=true` 的版本，也可以没有已上线版本。
- APK 和 WGT 更新统一执行强制更新流程。

## 4. 索引

```text
PRIMARY KEY (upgrade-app.id)
UNIQUE (upgrade-app.appid)
PRIMARY KEY (upgrade-app-versions.id)
INDEX (upgrade-app-versions.appid)
INDEX (upgrade-app-versions.appid, type, stable_publish)
INDEX (upgrade-app-versions.appid, createdTime DESC)
```
